# Synthetic Dataset Design for COPOD

## 1. Purpose

Construct labelled synthetic datasets to investigate how COPOD performs
when anomalies are unusual individual values versus unusual combinations
of otherwise ordinary values.

This document describes planned work. Generation and validation results
will be recorded separately after execution.

## 2. Data source

All observations will be generated using Python and explicitly specified
probability distributions.

The initial generator will not copy observations or estimate parameters
from an existing dataset. Its purpose is controlled experimentation,
rather than simulation of a particular real-world application.

Existing public datasets will provide a separate evaluation of performance
on real data.

## 3. Initial pilot

Start with two scenarios, each containing:

- 10,000 observations.
- 20 numeric predictor columns.
- 9,500 normal observations and 500 generated anomalies.
- An anomaly proportion of 5%.
- Seeds 42, 43, 44, 45 and 46 for five repeat runs.

First generate and validate seed 42. Expand to the remaining seeds after
the generator passes its checks.

These are manageable pilot settings, not parameters selected to maximise
COPOD's performance.

## 4. Normal observations

Generate features with standard normal marginal distributions:
population mean zero and standard deviation one.

Arrange the 20 features into four blocks of five features.

Within each block, set the population correlation between different
features to 0.8. Generate different blocks independently.

This creates observations with a known relationship structure.

## 5. Anomaly scenarios

### A. Marginal shifts

Generate observations using the normal process, then add either +4 or -4
to one randomly selected feature of each anomaly.

This tests detection of observations containing an unusually large or
small individual value.

The altered feature and shift direction will be recorded separately
from the model inputs.

### B. Dependence violations

Generate anomalies with 20 independent standard normal features.

Their individual feature distributions match those of normal observations,
but they lack the correlations present within normal feature blocks.

This tests detection of unusual relationships between features.

Matching marginal distributions is a population property; finite samples
will show some differences.

Each scenario will be stored separately so its results remain interpretable.

## 6. Labels and model inputs

- label = 0: generated by the normal process.
- label = 1: generated by the specified anomaly process.

Labels identify the generating process. They do not guarantee that every
anomaly is visibly unusual or perfectly separable from normal observations.

Only feature columns will enter the detector. Labels, identifiers,
scenario names and construction metadata will be excluded.

## 7. Validation before evaluation

Check and record:

- Dataset dimensions and exact class counts.
- Missing values and non-finite values.
- Duplicate observations.
- Feature means, standard deviations and quantiles.
- Correlations within and between feature blocks.
- Marginal distributions for each class.
- Scatter plots illustrating the intended anomaly mechanisms.
- Reproducibility when rerunning the same seed and configuration.

Investigate unexpected patterns before evaluating detectors.
Do not remove observations merely because a detector finds them difficult.

## 8. Evaluation plan

Use a reproducible, stratified 60/40 training/test split.

For each pilot dataset this gives:

- Training: 6,000 observations, including 300 anomalies.
- Testing: 4,000 observations, including 200 anomalies.

Fit COPOD using training predictors only. Use held-out labels to calculate
ROC AUC and average precision.

Any preprocessing requiring fitted parameters must use training data only.

Report individual seed results and their variation. Do not change the
generator to improve test scores.

Comparison detectors and wider experiments will be specified before
running those comparisons.

## 9. Planned extensions

After validating the pilot, extend the generator to investigate:

- Positively skewed and heavy-tailed marginal distributions.
- Different strengths of dependence.
- Dimensions of 5, 20 and 100.
- Anomaly proportions of 1%, 5% and 10%.
- Local anomalies and small anomalous clusters.

Define and validate each additional mechanism before use.

An independence-based anomaly mechanism requires dependent normal data.
If both processes are identical, treat that setting as a null control,
not as a meaningful anomaly scenario.

## 10. Output locations and reproducibility

- scripts/: generator and validation/evaluation code.
- data_new/synthetic/: generated datasets; excluded from Git.
- results/synthetic/: configurations, validation summaries and metrics.
- figures/synthetic/: diagnostic plots.
- notes/: design decisions, progress and limitations.

Record seeds, generation parameters, package versions and dataset checksums.
Keep code and small supporting evidence in Git so the datasets can be
regenerated.

## 11. Limitations

These controlled datasets cannot represent every real-world anomaly.

Conclusions apply to the tested generating processes and settings.
Results will be interpreted alongside the existing public datasets.
